# 사용 가이드 메모

화면을 간결하게 다듬으면서(2026-11-02) 앱 화면에서 뺀 설명을 모아 둔 것이다. 사용 가이드 문서를 쓸 때 재료로 쓰고, 다 옮기면 이 파일은 지운다. 동작이 바뀌면 이 메모가 아니라 코드와 설계 문서(`docs/`)를 기준으로 한다.

## 시작

- 프로젝트는 폴더 하나이고 CSV 파일이 원본이다. 폴더를 열면 그 안의 `project.json`을 읽고, 새로 만들면 기본값으로 `project.json`을 만든다.
- 새 프로젝트의 원문 언어는 나중에 프로젝트 화면에서 바꿀 수 있다.

## 프로젝트 화면

- `project.json`에 저장되는 설정이다. 게임 소개·톤 가이드·스타일 규칙은 번역 프롬프트의 고정 부분에 그대로 들어가고, 저장하면 다음 번역 작업부터 반영된다.
- `project.json`이 앱 밖에서 바뀐 채로 저장하면 이 화면에서 고친 묶음만 덮어쓰고, 밖에서 고친 다른 묶음은 그대로 남는다. [변경 취소]를 누르면 바뀐 내용으로 다시 채운다.
- 원문 언어는 번역 프롬프트, 에이전트 메모 언어, 용어집 매칭 방식에 쓰인다. 바꿔도 원문 파일 내용은 바뀌지 않는다.
- 대상 언어를 목록에서 빼도 `translations_{lang}.csv` 파일은 지우지 않는다. 다시 넣으면 그대로 이어서 쓴다.
- 게임 소개에는 세계관, 주요 인물, 플레이어가 하는 일 등 번역가가 알아야 할 배경을 적는다. 톤 가이드 예: "간결하고 경쾌하게. UI 는 명사형으로 짧게, NPC 대사는 캐릭터 말투를 살린다."
- 스타일 규칙은 모든 번역 배치에 들어가는 지속 지시다. 한 줄에 규칙 하나를 적는다. 에이전트 패널에서 제안된 규칙은 확인 카드에서 [저장]해야 들어가고, 저장한 뒤에는 이 화면에서 고치거나 지울 수 있다.
- 번역 모델과 사고 수준은 번역 화면에서도 고를 수 있고 같은 값이다. 사고 수준이 높을수록 더 오래 생각하고 사용량을 더 쓴다. 모델이 지원하지 않는 수준은 그 모델이 지원하는 수준으로 낮춰 실행된다.
- 배치는 행 수와 원문 글자 수 중 먼저 닿는 쪽에서 끊는다. 배치가 클수록 세션 수는 줄지만 한 번 실패할 때 다시 돌릴 양이 늘어난다. 동시 작업자는 1~3.
- 신뢰도 낮음 기준: 에이전트 신뢰도가 이 값보다 낮은 행을 검토 화면의 "신뢰도 낮음" 필터로 모으고, 초안 일괄 승인에서 뺀다.
- 최대 길이 배수: 에이전트가 제안하는 최대 길이는 원문 길이 × 이 배수(최소 글자 수 있음) 아래로 내려가지 않는다. 최대 길이는 번역문의 한도라서, 원문보다 번역이 길어지는 언어 조합이면 값을 키운다.
- 내보내기 카드는 Unity CSV 의 언어 열이다. 열 이름이 Unity 쪽과 한 글자라도 다르면 Unity 가 그 열을 조용히 무시한다. 빈 칸은 자동이다 — 로케일 코드는 프로젝트 언어 코드(Unity 프로젝트를 연결했으면 그 프로젝트의 로케일), 열 이름은 `{영어 언어명}({코드})`. 만들어질 헤더 전체는 내보내기 화면에서 보고, 처음 한 번은 Unity 에서 내보낸 CSV 의 첫 줄과 눈으로 비교해 본다.
- Smart Strings(고급): Unity 프로젝트의 SmartFormat 설정과 같게 맞춘다. QA 의 중괄호·변수·포매터 검사가 이 값을 따른다.
  - Smart Strings 사용: 끄면 포매터 이름 경고만 끈다.
  - 대체 이스케이프(alternativeEscaping): 켜면 이스케이프 문자 + 중괄호가 리터럴, 끄면 `{{ }}`.
  - 문자 리터럴 변환(convertCharacterStringLiterals): `\n`, `\t`를 문자로 바꾼다.
  - 대소문자 구분(caseSensitive): 변수·포매터 이름 비교에 쓴다.
  - 포매터 목록에 없는 이름은 경고로 표시한다. 커스텀 포매터를 등록했다면 목록에 더한다.

## 원문 화면

- `strings_master.csv`가 원본이다. 원문과 메타데이터를 고치고 저장하면 CSV에 바로 반영된다.
- 원문 파일이 없으면 빈 파일을 만들어 행을 직접 추가하거나, [원문 가져오기]로 기존 CSV를 불러온다. 행을 추가하고 저장해도 파일이 만들어진다.
- 파일이 앱 밖에서 바뀌면, 편집 중일 때는 자동으로 다시 읽지 않는다. 저장할 때 충돌을 확인한다.
- 행 추가: 고른 행 바로 아래(없으면 맨 끝)에 넣는다. 저장하기 전에는 [행 삭제]로 바로 지울 수 있다. 저장한 뒤에는 키를 바꿀 수 없다 — 번역과 내보내기가 키로 연결된다.
- 행 삭제: 저장하면 `strings_master.csv`와 폴더의 모든 번역 파일(`translations_*.csv`)에서 그 키의 행을 지운다. 저장하기 전에는 [변경 취소]로 되돌릴 수 있다.
- [변경 취소]는 저장하지 않은 편집, 추가한 행, 순서 변경, 삭제 대기를 모두 버리고 디스크의 파일을 다시 읽는다.
- [Smart 제안 적용]: 원문에 Smart 구문(플레이스홀더)이 있는데 Smart 칸이 미정인 행을 Smart 로 둔다. 일반으로 둔 행은 건드리지 않는다.
- 원문 가져오기: 매핑하지 않은 열은 기존 값을 그대로 둔다. 이번 파일에 없는 키는 지우지 않고 목록으로만 알린다.
- 행 순서는 끌어서 바꾸거나 Alt+↑/↓ 로 옮긴다.

## 컨텍스트 화면

- 에이전트가 원문의 빈 메타데이터 칸(컨텍스트·UI 유형·최대 길이·변수 설명)을 제안한다. 제안은 `context_suggestions.csv`에 쌓이고, 여기서 고치고 적용한 행만 `strings_master.csv`에 들어간다. 이미 채워진 칸은 건드리지 않고, 메타데이터는 번역 상태를 바꾸지 않는다.
- 최대 길이는 버튼·탭처럼 길이 제한이 분명한 짧은 UI 문구에만 제안한다. 원문 길이 × 배수(프로젝트 화면) 이상으로 넉넉하게 제안한다.
- 선택 행 범위에서도 고른 필드가 모두 채워진 행은 건너뛴다.
- 모델·사고 수준·배치·작업자는 프로젝트 화면의 번역 설정을 따른다.
- 제안을 버려도 원문은 바뀌지 않는다. 다시 추정하면 그 행을 다시 제안받을 수 있다(사용량을 다시 쓴다).

## 용어집 화면

- `glossary.csv`의 용어와 언어별 확정 번역이다. 승인된 용어만 번역 배치에 들어가며, 배치마다 그 배치 원문에 나오는 용어만 넣는다. strict 를 켠 용어는 어기면 QA 오류가 되어 내보내기를 막는다.
- 대상 언어를 정하면 언어별 번역 칸이 생긴다.
- 용어 추출: 에이전트가 원문에서 고유명사·게임 용어 후보를 찾는다. 후보는 번역 없이 승인 대기로 들어가고, 이미 있는 용어는 다시 넣지 않는다. 번역은 [용어 번역]으로 채운다.
- 용어 번역: 에이전트가 용어집의 빈 번역 칸을 채운다. 원문 예문과 다른 언어의 번역을 참고하고, 이미 있는 번역은 덮지 않는다(다시 받으려면 [선택 재번역]). 승인된 용어에 채운 언어는 승인 대기로 표시되어 [선택 승인] 전까지 번역과 QA 에 쓰이지 않는다.
- 용어 추가: 원문에서 이 용어가 쓰인 문장(과 기존 번역)을 찾아 에이전트가 번역을 채운다. 품사·분류와 사용 지침은 비워 두면 에이전트가 채운다. 결과는 승인 대기로 들어가니 그리드에서 확인하고 승인한다.
- 선택 재번역: 원문에서 이 용어가 쓰인 문장과 기존 번역을 함께 보고 번역을 다시 정하고, 사용 지침도 새 번역에 맞게 다시 쓴다. 품사·분류는 바꾸지 않는다. 결과는 그 행의 칸에 채워지고, 확인한 뒤 [저장]해야 반영된다. 지시 예: "영어는 더 짧게, 일본어는 가타카나로".
- 같은 용어가 `glossary.csv`에 여러 행 있으면 첫 행만 고칠 수 있다.
- 승인된 용어를 지우면 번역 프롬프트와 QA 에서 빠진다.

## 번역 화면

- 배치마다 새 에이전트 세션을 열어 번역하고, 검증을 통과한 배치만 번역 파일에 한 번에 기록한다. 승인된 행은 어느 범위에서도 건드리지 않는다.
- 범위: 미번역(번역이 없거나 빈 행), stale(원문이 바뀐 행), 전체(승인되지 않은 모든 행 — 초안·검토 번역도 다시 쓴다), 선택 행.
- 배치 크기와 작업자 수는 프로젝트 화면(`project.json`의 `batch`)에서 바꾼다.
- 다른 작업(컨텍스트 추정·용어 추출 등)이 도는 중에는 끝난 뒤에 시작할 수 있다.

## 작업 진행(모든 배치 작업 공통)

- 사용량 한도에 걸리면 모든 작업자를 멈추고, 진행 중이던 배치는 기록하지 않고 다시 돌린다. 재설정 시각을 알면 그때 자동으로 다시 시작하고, 모르면 백오프로 기다린다. 자동 재시도가 멈추면 한도가 풀린 뒤 [지금 재시도]를 누른다.
- 실패한 배치는 기록하지 않는다. 같은 조건으로 다시 실행하면 남은 것만 처리한다.
  - 번역: 같은 범위로 다시 번역하면 그 행만 다시 돈다.
  - 컨텍스트 추정: 아직 제안이 없는 행만 돈다.
  - 용어 추출: 이미 있는 용어는 다시 넣지 않는다.
  - 용어 번역: 아직 빈 칸만 채운다.

## 검토/QA 화면

- 번역 칸을 고치면 그 행만 바로 저장되고 초안이 된다. QA 오류가 있는 행은 승인할 수 없고, 내보내기에서도 막힌다.
- 번역 작업이 진행 중이면 배치가 기록될 때마다 다시 읽는다. 작업이 시작된 뒤 여기서 고친 행은 작업이 덮어쓰지 않는다.
- 단축키: ↑↓ 이동 · Enter(또는 더블클릭) 편집 · Ctrl+Enter 저장 · Esc 취소.
- "신뢰도 낮음" 필터의 기준은 프로젝트 화면의 신뢰도 낮음 기준(`review.lowConfidence`)이다.
- 재번역: 일회성 세션으로 그 행만 다시 번역해 후보를 받는다. 지시 예: "더 짧게, 존댓말로, 용어 '바벨탑' 유지". 승인된 행에 후보를 적용하면 번역이 바뀌고 초안으로 돌아간다.
- 원문 변경(stale) 행은 번역할 때 본 원문과 지금 원문의 차이를 보여 준다. 이전 원문은 번역을 기록할 때 함께 남기므로, 이 기능이 생기기 전에 번역한 행이거나 번역 파일을 앱 밖에서 고친 행은 기록이 없다.
- 초안 일괄 승인: 지금 목록에 보이는 초안 중 QA 오류·경고가 없고 신뢰도가 기준 이상인 행(신뢰도가 없는 행 — 사람이 고친 초안 — 포함)을 승인한다. 저장 직전에 파일을 다시 읽어 조건을 다시 확인하고, 그 사이 바뀐 행은 건너뛴다. 승인한 행은 배치 번역이 덮어쓰지 않는다. 되돌리려면 행을 골라 [초안]이나 [검토]로 바꾼다.

## 내보내기 화면

- Unity Localization 의 String Table 컬렉션으로 가져올 CSV 를 만든다. 기본은 Unity CSV 확장의 기본 열 구성으로 자동 생성하고, Unity 프로젝트 연결과 템플릿은 필요할 때만 쓴다.
- 내보낼 언어에서 뺀 언어의 열은 만들지 않는다. Unity 는 그 로케일을 건드리지 않는다.
- 주석 열(Shared Comments·언어별 Comments): 칸이 비어 있으면 Unity 의 기존 주석이 지워진다. 옵션을 끄면 열을 만들지 않아 Unity 주석을 그대로 둔다.
- 미번역·원문 변경 칸 처리:
  - 비우기: Unity 에 이미 있는 그 언어의 번역은 빈 값으로 덮인다.
  - 원문 넣기: 번역이 없거나 원문이 바뀐 칸에 원문을 그대로 넣는다.
  - 행 빼기: 고른 대상 언어 중 하나라도 비는 행을 뺀다. Import > CSV(Merge)... 로 가져와야 Unity 의 그 행이 남는다.
- 파일 이름을 비우면 연결한 컬렉션 이름, 없으면 프로젝트 이름을 쓴다.
- Unity 프로젝트 연결(선택): Unity 프로젝트의 로케일 에셋과 String Table 공유 데이터 에셋을 읽어 실제 로케일 코드와 기존 키의 Id 를 가져온다. 읽기만 하고 Unity 프로젝트에 쓰지 않는다. 읽지 못하면 기본 자동 생성으로 내보낸다.
- 템플릿(선택): Unity 쪽 CSV 확장에서 열 이름이나 구성을 바꾼 경우에만 필요하다. Unity 에서 내보낸 CSV 를 등록하면 그 열 이름과 순서를 따른다. 열마다 역할을 확인하고, 매핑을 저장해야 미리보기와 내보내기에 반영된다. 역할을 "내보내지 않음"으로 둔 열은 내보내지 않는다.
- 헤더 미리보기: 열 이름이 Unity 쪽과 다르면 Unity 는 그 열을 오류 없이 건너뛴다. 처음 한 번은 Unity 에서 내보낸 CSV 의 첫 줄과 비교해 본다. 언어별 코드·열 이름은 프로젝트 화면 "내보내기" 카드에서 고친다.
- QA: 번역문을 그대로 내보내는 칸만 검사한다. 비우거나 원문으로 채우는 칸의 옛 번역은 Unity 로 가지 않는다. 경고는 내보내기를 막지 않는다. 오류는 [검토에서 보기]로 그 행을 열어 고친다.
- Smart 항목: Unity CSV 는 Smart 여부를 옮기지 않는다. 목록을 `{이름}_smart.csv`로도 쓰니, Unity 에서 이 항목들을 Smart 로 표시한다. Smart 칸이 미정인 행은 원문 화면의 [Smart 제안 적용]으로 정한다.
- Unity 에서 가져오기: Localization Tables 창에서 컬렉션을 고르고 Import 메뉴의 **CSV(Merge)...** 를 고른다. **CSV...** 는 파일에 없는 키를 컬렉션에서 지운다.

## 에이전트 패널

- 프로젝트에 대해 묻거나 "앞으로 NPC 대사는 반말로"처럼 지속 지시를 준다. 지속 지시는 규칙 카드에서 [저장]을 눌러야 `project.json`의 스타일 규칙에 들어가고, 다음 번역 배치부터 반영된다. 저장한 규칙은 프로젝트 화면에서 고치거나 지울 수 있다. [무시]한 지시는 번역 배치에 반영되지 않는다.

## 설정 화면

- 화면 언어는 한국어와 English 중에서 고른다. 고른 적이 없으면 Windows 표시 언어를 따른다(한국어면 한국어, 그 밖은 영어). 고르면 다시 시작하지 않고 바로 바뀐다. 에이전트가 쓰는 메모·컨텍스트는 화면 언어와 상관없이 원문 언어로 쓴다.
- 에이전트는 Claude Code 를 통해 실행되고, Claude Code 에 로그인한 방식(Claude 구독 또는 API 키)을 그대로 쓴다. 어떤 방식으로 인증할지는 Claude Code 의 로그인 상태(환경 변수 `ANTHROPIC_API_KEY` 포함)를 그대로 따른다.
- 앱은 로그인 코드·토큰·API 키를 받지도 보관하지도 않는다. 로그인은 Claude Code 가 새 창에서 진행한다 — 그 창과 브라우저에서 로그인을 마치고, 코드를 붙여넣으라고 하면 그 창에 붙여넣는다. 창이 닫히면 로그인 상태를 다시 읽는다.
- [Claude 계정(구독)으로 로그인]은 Claude Pro·Max 등 구독 계정, [Console(API 과금)로 로그인]은 Anthropic Console 계정(사용량은 API 요금으로 청구)이다. 구독이면 사용량 한도 막대를 보여 주고, API 키면 사용량과 요금은 Claude Console 에서, 클라우드 제공자 계정이면 그 제공자의 콘솔에서 본다.
- 실행 파일 경로: 비워 두면 공식 설치 위치(`%USERPROFILE%\.local\bin`) → PATH 순으로 찾는다. 로그인·상태 조회와 번역 세션이 모두 이 실행 파일을 쓴다. 다른 Claude Code 를 쓰려면 지정한다. 찾지 못하면 명령 프롬프트에서 `claude --version`이 동작하는지 확인하고 그 경로를 입력한다.
- 설정 폴더: CLI 는 이 폴더에서 로그인 정보를 읽는다. 앱을 탐색기에서 실행하면 환경 변수가 없어 `~/.claude`를 보게 되므로, 다른 폴더에 로그인했다면 그 경로를 지정한다.
- Claude Code 버전이 앱이 맞춰진 최소 버전보다 낮으면 일부 기능이 동작하지 않을 수 있다. [업데이트 확인]으로 맞춘다.
- 앱 업데이트: 켤 때와 켜 둔 동안 6시간마다 GitHub Releases 에서 새 버전을 확인한다. 받기는 [받기]를 눌러야 시작한다. 받아 둔 업데이트는 [다시 시작해 설치]를 누르거나 앱을 끌 때 설치된다. 작업이 도는 중에는 다시 시작하지 않는다.

## Claude Code 시작 확인

- 번역 에이전트는 Claude Code 로 실행된다. 앱을 켤 때 Claude Code 를 찾아 최신으로 업데이트하고, 끝날 때까지 기다린다.
- Claude Code 가 없으면 [설치]가 새 창에서 Anthropic 의 공식 설치 스크립트(`irm https://claude.ai/install.ps1 | iex`)를 실행한다. 관리자 권한은 필요 없고, 설치된 Claude Code 는 스스로 업데이트된다. 설치 창에서 끝나면 Enter 를 눌러 닫고, 창이 닫히면 다시 확인한다.
- 설정한 경로의 Claude Code 를 실행하지 못하면, 설정 화면에서 경로를 비워 설치된 Claude Code 를 자동으로 찾게 한다.
- 새로 업데이트된 직후에는 첫 실행이 백신 검사 등으로 오래 걸려 응답하지 않을 수 있다. 잠시 뒤 다시 시도한다.

## 파일 충돌

- 저장하려는 파일이 앱 밖에서 바뀌었으면 충돌 대화상자가 뜬다. [덮어쓰기]는 앱 밖에서 바뀐 내용을, [다시 불러오기]는 지금 편집 중인 내용을 버린다.
- 저장하지 않은 변경이 있는 채로 다른 화면으로 가거나 프로젝트를 닫거나 업데이트를 설치하려고 다시 시작하면 확인을 받는다.
