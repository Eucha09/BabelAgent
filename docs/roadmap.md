- 기계적으로 확인한 것: `npm run typecheck` 통과, `npm test` 12개 통과, `npm run build` 성공, 빌드 산출물로 앱 기동 시 렌더러 콘솔 오류 0건, Agent SDK의 `accountInfo()`와 `stream_event` 델타를 로컬 CLI로 실측. **UI를 클릭해 거친 경로는 없다** — 아래 확인 항목을 사용자가 통과시킨 뒤 `[x]`로 바꾼다.

- `tsconfig`를 main/renderer로 분리하지 않고 루트 하나로 전체를 검사한다. composite/references 조합의 도구 호환성 문제를 피한 선택이며, 프로세스 경계는 electron-vite 빌드 분리와 리뷰로 지킨다. 분리가 필요해지면 그때 쪼갠다.
- CSP는 `electron.vite.config.ts`의 `cspPlugin`이 프로덕션 빌드에만 주입한다. 개발 모드에서는 React Refresh의 인라인 스크립트와 충돌한다. 패키징 시 커스텀 프로토콜 도입을 함께 검토한다.
- 단계 화면 6개를 개별 파일로 만들지 않고 `state/screens.ts` 정의 + `Placeholder` 한 컴포넌트로 처리했다. 실제 기능이 들어가는 마일스톤에서 화면별 파일로 분리한다.
- 앱 아이콘은 3단 바벨탑이다. 층을 두껍게(각 5.6 단위) 잡고 층마다 아치형 출입구를 팠으며, 위 두 층은 3.5도 기울이고 기단은 수평으로 둔다. 아치는 배경색으로 덮은 것이 아니라 외곽선에 파낸 구멍이라 상단 바에서 글자색을 따라가도 뚫려 보인다. 원본은 `build/icon.svg` 하나이고, 래스터(`icon.png` 512, `icon.ico` 256)와 상단 바용 `AppIcon.tsx`는 `npm run icon`(= `scripts/make-icon.cjs`)이 함께 만든다. 래스터는 Electron 창에 SVG를 띄워 `capturePage`로 뜬다 — 이미지 라이브러리 의존성이 없다. ICO는 PNG를 그대로 품는 형식이라 Windows Vista 이상에서 읽힌다. 모양을 바꿀 때는 SVG만 고치고 이 명령을 다시 돌린다.
- 계정 카드에 구독 한도 막대를 넣었다(5시간·주간, 남은 비율과 초기화까지 남은 시간). 출처는 `/usage` 로컬 명령이 돌려주는 구조화된 `usage_report.rate_limits.limits[]`이며, 같은 명령의 텍스트 출력은 쓰지 않는다. CLI를 띄우는 조회라 설정 화면을 열었을 때 한 번만 읽고, 남은 시간은 30초마다 다시 센다.
- 설정 화면에 계정 카드를 넣었다. `claude auth status --json`으로 로그인 계정·조직·구독·설정 폴더를 보여주고, `claude auth login --claudeai`를 띄워 앱 안에서 로그인한다(브라우저가 열리고, 코드 입력을 요구하면 stdin으로 전달). 상태바도 연결 확인 전에는 이 상태를 보여준다.
- 인증 실패(`authentication_failed`) 원인은 **CLI 설정 폴더**였다. 터미널 밖(탐색기/`run-dev.bat`)에서 실행하면 `CLAUDE_CONFIG_DIR`이 없어 CLI가 `~/.claude`를 보는데, 그 폴더의 토큰이 비어 있으면 CLI는 뜨고 API 호출만 실패한다. 대응: 앱 설정에 `claudeConfigDir`를 추가해 `options.env`로 전달하고(이 `env`는 환경을 통째로 교체하므로 `process.env` 스프레드가 필수), 인증 오류 detail에 실제로 사용한 설정 폴더 경로를 붙인다. 연결 확인 결과에도 설정 폴더를 표시한다.
- `run-dev.bat`(저장소 루트)을 두 번 누르면 의존성 설치 → Electron 바이너리 확인 → `npm run dev` 순서로 알아서 띄운다. Electron 44가 postinstall 없이 설치되는 문제를 이 스크립트가 흡수한다. 내용은 영어로 작성.
- 버전 고정: TypeScript 5.9.3, `@vitejs/plugin-react` 6.1.2(vite 8 지원 버전), `vitest.config.mts`(ESM이어야 Vite 설정 로더 경고가 없다).
- SDK 타입 실측 결과 웹 문서와 다른 점: 부분 메시지 타입은 `partial_assistant`가 아니라 **`stream_event`**이고 `event`에 Messages API 스트리밍 이벤트가 담긴다. `settingSources`를 생략하면 모든 설정을 읽으므로 `[]`를 반드시 넘겨야 한다. 내장 도구는 `tools: []`로 전부 끈다.
- 실측 검증(로컬 CLI, 2026-10-19): `accountInfo()`가 스트림 소비 없이 계정 정보를 돌려줬고, 짧은 프롬프트로 `stream_event` 델타 3건과 `result.subtype = success`를 확인했다.

- 추가(2026-10-20): 원문 화면에 [빈 원문 파일 만들기], [행 추가], 행 순서 바꾸기(손잡이 끌어서 놓기, ↑↓ 버튼, `Alt+↑↓`)를 넣었다. 저장 전 새 행은 [새 행 제거]로 되돌릴 수 있다. 순서 이동·키 검사는 `src/core/strings/order.ts`·`keys.ts`에 두고 테스트했으며, 실제 파일에 순서가 보존되는 것은 store 통합 테스트가 확인한다. 그리드 행 정체는 인덱스가 아니라 키(`getRowId`)라서 순서를 바꿔도 편집 중인 칸의 포커스가 다른 행으로 튀지 않는다.

- 배치 결과는 텍스트 JSON 이 아니라 `submit_translations` 도구로 받는다. 입력 스키마가 곧 zod 검증이라 "JSON 파싱 실패" 경로가 없다. 핸들러가 키 집합·빈 번역을 검사하고, 통과한 제출을 보관했다가 세션이 끝나면 배치 단위로 한 번에 기록한다.
- 배치 세션의 도구는 `submit_translations` 하나뿐이다. 데이터는 프롬프트에 다 넣는다. 읽기 도구 셋(`get_project_context`, `get_strings_batch`, `get_glossary_terms`)은 패널 채팅에 붙였다.
- 시스템 프롬프트 = 고정 부분(역할·게임 소개·톤 가이드·스타일 규칙 id 순·언어 지시)으로 작업마다 한 번 만들어 모든 배치가 같은 문자열을 쓴다. 지시문은 영어로 쓰고 사용자가 쓴 내용은 그대로 넣는다.
- **검증 4단계 중 QA(변수·태그 집합)는 M4로 미뤘다.** Smart Strings 토크나이저가 M4 항목이라서다. 키 검사 뒤에 끼울 자리만 있다.
- 용어집은 `glossary.csv` 가 있으면 승인된 용어를 대소문자 무시 부분 일치로만 걸러 넣는다. 제대로 된 매칭은 M4/M5.
- 계획했던 파일별 잠금은 넣지 않았다. 번역 파일의 다시 읽기 → 병합 → 쓰기가 동기 함수 하나라 같은 프로세스의 다른 작업자가 끼어들 수 없다.
- 통과한 제출이 있으면 그 뒤 한도 대기로 중단 신호가 와도 기록한다(배치가 온전함). 중단된 배치는 끝나기까지 몇 초 걸려서 화면에 "정리 중"으로 보인다.
- 한도 감지: `rate_limit_event`(rejected, 재설정 시각) → `assistant.error === rate_limit` → 결과 `errors`·예외 문장 순. `resetsAt` 단위가 문서에 없어 초·밀리초를 모두 받는다. **실제 한도는 아직 겪어 보지 못했다** — 가짜 한도(`BABEL_FAKE_LIMIT=1`)와 단위 테스트로만 확인.
- 실측(2026-10-20, haiku): 3행 배치 하나 7.3초. 앱에서 8행 · 배치 3개 · 작업자 2로 가짜 한도 → 20초 대기 → 자동 재개 → 완료까지 약 50초. `{playerName}`, `{level}`, `<color=#ff0000>…</color>` 모두 보존됐고 확신이 낮은 행은 `note` 에 이유를 남겼다.
- 테스트 200개(+80). 스케줄러는 배치 실행기와 시계를 주입받아 가짜 한도로 시험한다. 실제 SDK 를 부르는 시험은 사용량을 쓰므로 스위트에 넣지 않았다 — Vitest VM 에서는 `new Function` 동적 import 가 안 돼서 그런 시험은 SDK 로더를 `vi.mock` 으로 바꿔 끼운다.
- M4 이후로 넘긴 것: QA 검증 단계, 실패한 배치만 골라 다시 돌리기(지금은 같은 범위로 다시 실행하면 그 행만 돈다), 작업 비용 표시, `update_project_rules`·`propose_glossary_terms`(M5).
