# Unity Localization 내보내기

## 원칙

열 이름과 순서를 코드에 박지 않는다. Unity Localization의 CSV 확장은 프로젝트 설정(로케일 구성, 주석 열 포함 여부, 열 이름)에 따라 결과가 달라지므로, **사용자가 Unity에서 한 번 내보낸 CSV를 템플릿으로 삼아 그 구조를 그대로 재현한다.**

템플릿 경로는 project.json의 `export.unityTemplate`에 저장한다.

## 템플릿 해석

1. 템플릿의 첫 줄(헤더)만 읽어 열 이름 배열을 얻는다.
2. 각 열을 역할에 매핑한다.
   - 키 열: `Key`, `Id` 등 — 후보 이름 목록으로 추론
   - 공용 주석 열: `Shared Comments` 등
   - 로케일 값 열: 열 이름에 로케일 코드가 포함된 열 (`English(en)`, `Korean(ko)`, `ko` 등)
   - 로케일 주석 열: 로케일 코드 + 주석 표기가 함께 있는 열
3. 추론 결과를 내보내기 전에 UI로 보여주고 사용자가 수정할 수 있게 한다. 매핑 결과는 project.json에 저장해 다음 내보내기부터 재사용한다.
4. 자동 추론에 실패한 열은 "비워 둠"으로 처리하고 경고한다. 추측으로 채우지 않는다.

출력은 템플릿의 **열 이름과 순서를 그대로** 쓴다. 템플릿에 없는 열을 추가하지 않는다. Babel Agent 내부 열(`status`, `confidence`, `note`, `source_hash`)은 내보내지 않는다 — Unity가 모르는 열이다.

## 행 생성

- 대상은 `strings_master.csv`의 key 전체(사용자가 범위를 좁힌 경우 그 범위).
- 각 로케일 열은 해당 `translations_{lang}.csv`의 `text`로 채운다.
- 원문 로케일 열(`sourceLanguage`)은 `strings_master.csv`의 `source`로 채운다.
- 미번역/stale 행 처리는 내보내기 옵션으로 고른다. 기본값은 **빈 값으로 내보내기**.
  - `empty`(기본): 값을 비운다. Unity가 폴백을 쓰게 한다
  - `source`: 원문을 넣는다
  - `skip`: 행 자체를 제외한다
- 어떤 옵션이든 내보낸 행 수와 비워 둔 칸 수를 결과 요약에 보고한다.

## 차단 조건

- QA `error`가 하나라도 있으면 내보내기를 막는다. 진단 목록을 보여주고 해당 행으로 이동할 수 있게 한다.
- `warning`은 막지 않지만 요약에 개수를 표시한다.
- 템플릿 파일이 없거나 헤더를 읽을 수 없으면 내보내기를 막고 템플릿 재지정을 요구한다.

## 쓰기

- UTF-8, BOM 없음, 줄바꿈 `\n`, `csv-stringify` 사용.
- 임시 파일에 쓴 뒤 원자적으로 교체한다. 기존 파일을 덮어쓸 때는 사용자 확인을 받는다.
- 내보낸 값이 템플릿을 왕복해도 동일해야 한다. 쉼표·줄바꿈·따옴표·Smart Strings 중괄호가 든 문자열로 왕복 테스트를 작성한다.

## 테스트

- 열 추론: 로케일 코드 표기가 다른 헤더 여러 종류에 대해 매핑 결과를 고정한다.
- 열 순서 보존: 템플릿 헤더 순서를 섞어도 출력이 따라가는지 확인한다.
- 미번역 처리 세 가지 옵션의 출력 비교.
- 특수문자 왕복.
